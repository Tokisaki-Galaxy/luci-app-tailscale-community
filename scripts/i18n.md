# Translation maintenance

`scripts/i18n.py` regenerates the template and syncs the `.po` files. It is a
standalone replacement for openwrt/luci's `build/i18n-sync.sh`, which drives
Perl scripts and needs `xgettext`, `msgmerge` and `msguniq` from the gettext
toolchain. This needs only the Python standard library, so it runs on Windows
without any setup.

## Usage

```powershell
# regenerate the template and merge every language
python scripts/i18n.py

# only regenerate po/templates/community.pot
python scripts/i18n.py --pot

# one language only
python scripts/i18n.py --lang zh_Hans

# CI mode: exit 1 when anything is out of date
python scripts/i18n.py --check
```

## What it does

1. **Extract.** Scans the package for translatable strings:
   - `htdocs/**/*.js` for `_('...')` and `N_('...')` calls
   - `root/usr/share/luci/menu.d/*.json` and `root/usr/share/rpcd/acl.d/*.json`
     for `title` and `description` values

2. **Write the template.** `po/templates/community.pot` is rewritten with one
   entry per unique string, sorted, with `file:line` references.

3. **Merge.** Each `po/<lang>/community.po` is rebuilt from the new template:
   - strings that still exist keep their translation
   - new strings are added untranslated
   - strings that disappeared from the source are kept as `#~` obsolete
     entries with their translation, so if the string comes back it is still
     translated

## Differences from the upstream tool

- No gettext binaries required.
- Long msgids wrap the same way, but the line-break points may differ from
  `xgettext`'s, so the first run over an existing file shows a large diff that
  is almost entirely reflow.
- Obsolete entries are preserved instead of being pruned by `msgmerge`.
- `--check` is available for CI; upstream has no equivalent.

## Verifying the output

The generated files are plain gettext, so the real tools accept them:

```sh
msgfmt --check-format -o /dev/null luci-app-tailscale-community/po/templates/community.pot
```

On Windows without gettext, `--check` plus a round-trip through the parser is
the next best thing.

## Formatting rules

- `msgid` and `msgstr` are always quoted, even when empty.
- Strings longer than 70 characters are split into a `""` header plus
  continuation lines.
- The header is `msgid ""` / `msgstr "Content-Type: text/plain; charset=UTF-8\n"`.
- Files are UTF-8 with `\n` line endings, regardless of platform.
